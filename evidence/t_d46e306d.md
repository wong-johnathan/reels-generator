1. **"package contents … inspectable"**
   S-16 renders five rows (MP4, .srt, .vtt, metadata sidecar, source manifest)
   with name, kind/format detail, byte size and the full SHA-256, plus one
   download per file and a "Download package" summary carrying the file count
   and total. Built state: `evidence/f-09/export-built-1440.png`.
   Model tests: `tests/web/export-model.test.ts` ("lists all five files…",
   "summarises the package as a file count…"); renderer tests:
   `tests/web/export-page.test.ts` (5 rows, 5 links, full hashes, 5-file
   download summary).
2. **"per-stage pins inspectable"**
   All eleven stages (`T, RS, SC, SB, IM, NA, TC, RE, QC, FA, EX`) are listed in
   order with pin (`vN` or `—`), the source of the pin (`package` when the
   export view recorded it, otherwise the video's current pin) and the stage
   state. The summary line is `v3` when uniform and `v2 ×3 · v3 ×8` when mixed;
   `Series version ids` exposes the full UUIDs. `pins: v2 ×3 · v3 ×8` and the
   `Per stage: …` line are visible in the 1440 capture.
   Tests: `export-model` ("covers all eleven stages…", "summarises a mixed set
   oldest-first…", "renders the bare version when every stage agrees"),
   `export-page` ("lists all eleven per-stage pins in stage order").
3. **"attempt rows paginated newest-first (last 50)"**
   `GET /health?video=<uuid>&stage=<code>` renders at most 50 attempt rows,
   sorted by `created_at` descending with the server order preserved for ties,
   labelled `last 50`, with the stated limit line: "Newest first, up to 50 rows."
   / "Showing the newest 50 attempt rows. The attempts endpoint takes a limit but
   no offset, so older rows are not paged here."
   Tests: `health-model` ("orders newest first…", "filters by stage before
   applying the 50-row page" — 120 rows → 50 shown, truncated), `health-page`
   ("states the page limit…"), `app-ops` ("lists the selected video attempt

   Capture: `evidence/f-09/health-attempts-1440.png` (timeout row reads
   **unknown charge** with a structural left bar — R-012-4).
4. **S-21 "key presence + qualification status only, never key values"**

## Supporting acceptance

- **R-014-1 / R-002-4 / UX A-24/A-25** — file list, pins and the manifest are
  all driven by the contract `ExportView`; nothing is invented when the package
  does not exist (the panel lists the five expected kinds and says they appear
  once built).
- **R-005-3 gate** — while FA is not approved the panel is `not_eligible`,
  prints the exact line "Not eligible for export. Final approval is required
  first.", disables download and build with that reason, and links to Render.
  Capture: `export-not-eligible-1440.png`.
- **R-012-4 / AX-26** — `timed_out`, `unknown_charge` and `charge_status:
unknown` all render "unknown charge", never "unbilled" (`health-model`
  "says unknown charge for a timeout, whatever the charge status").
- **R-018 readiness contract** — `/health` renders the five-part degraded block
  (cause, blocked, still works, system, next action), provider states, queue,
  disk percent with a text equivalent, and migration status; the shell's own
  degraded banner is suppressed there so the condition is stated once.
- **Accessibility** — one `h1`, h3/h4 hierarchy, table captions, labelled stage
  filter, `aria-describedby` on disabled controls, discernible download names,
  `progress` text, structural (non-colour) status, 44 px targets, visible focus
  rings: `tests/web/operations-a11y.test.ts`, `operations-styles.test.ts`.
- **Responsive** — 1440/768/390 captures; no page-level horizontal overflow at
  390 (document scrollWidth == innerWidth); the package table becomes a stacked
  list ≤767 and the pins/attempt tables scroll inside labelled regions.

## Deviations and gaps (no silent fixes)

- `contract/mock/fixtures.ts`: `health.report.disk.headroom_ok` changed
  `true → false`. 38 GB of 220 GB is 17 %, the report already lists the disk
  component as degraded and the overview says "disk headroom below 20 %"; the
  old value made the disk row contradict its own degraded state. No schema
  change.
- `export.get` carries no build error detail, so the failed state says the
  failing step is not reported and offers a retry; `export.build` is the only
  build affordance available.
- The attempt row has no `billed_units` field (S-19-2 gap), so no units column
  and no totals are shown; the page states both (D2).
- `/health` filtering is a server GET form (no client JS); the URL is the state.
- Hotspot: `src/web/app.ts`, `src/web/authPreview.ts`,
  `src/web/render/workspace.ts`, `src/web/styles/embed.ts`/`embedded.ts` are
  touched by F-08 and every other tab card, so this branch will conflict on
  merge; `operations.css` is additive and self-contained.
