## 4. Decisions (recorded, not silently taken)

1. **One schema authority.** `DOCUMENT_SCHEMAS` is B-04's `TEXT_SCHEMAS`, not a second copy. The adapter's response_format, the parse, the qualification hash and this harness therefore cannot disagree about "script.v1" (B-04 handed this over in its follow-ups).
2. **Ceiling = 3 total attempts.** R-004-2 says "retried at most 3 times"; UI_SPEC §6 (S-10) renders "schema attempt 2 of 3" / "3 of 3" and UI_SPEC §8's copy is "after 3 attempts". Three attempts satisfies both and matches B-08's 3-attempt transport ceiling, so a job never exceeds three failed calls of either kind. `maxAttempts` may be lowered, never raised (RangeError above 3).
3. **A failure carries no document.** `billable_downstream_calls: 0` is a type-level literal, and `blocked_stages` lists the producing stages the job will not reach. This is how "stops before any billable stage" is enforced here; the three failed text attempts are themselves billed calls recorded as separate `generation_run` rows (TECH_DESIGN §5.5, B-04), which is why the surfaced copy says _downstream_ (see §5.2).
4. **Word budget is measured on the spoken narration** (hook + narration + ending), not on the `narration` field alone: the fixture's `narration` field is 195 words but the spoken script is 231, i.e. the 228-word target applies to what is actually voiced.
5. **8-gram: maximal run, symmetric normalisation, per-field.** A 10-word lift is one violation naming 10 words; case/punctuation/line-break changes do not launder a run; words never join across field boundaries. Violation strings are what `script_revision.eight_gram_violations` / `ScriptView.eight_gram.violations` store.
6. **Storyboard tolerances.** `targetSceneCount = round(target / (75/17))` (75 s → 17, 10 s → 2); band = ±20 % widened to ±1 for small counts (75 s → 14–20, 10 s → 1–3, matching R-009-2's "a 10 s video may need 1–3 scenes").
7. **Non-factual claims** are mapped as `non_factual` and excluded from the source manifest (TECH_DESIGN §8.3: "Non-factual reworded claims are excluded"). Creative mode returns no rows at all (R-027-4).

## 5. Findings raised, not silently resolved

### 5.1 Word-band off-by-one in the frozen calibration module

`src/shared/calibration.ts` is techlead-owned and frozen (LEAD_PLAN §1). Its `wordBudget(75)` returns `{target_words: 228, min_words: 217, max_words: 239}`:

```
Math.round(228 * 0.95) = 217     // 216.6
```

but LEAD_PLAN §1 / QUALIFICATION §2 / UI_SPEC S-10 pin the band as **216–239**. Deriving the band from the ±5 % _duration_ band instead gives `floor(75*0.95*3.035) = 216` and `floor(75*1.05*3.035) = 239`. B-09 uses the frozen function rather than forking constants, so the current code reports 217–239; the recommendation is for the techlead owner to change `wordBudget`'s minimum to the duration-derived floor (216) so S-10 renders the pinned band. Raised in the task comment (see §8).

### 5.2 UI copy vs billing truth

UI_SPEC §8's failure copy ends "No billable stage ran." TECH_DESIGN §5.5 says the schema-invalid call _did_ bill and that R-004-2's attempts are new billable runs. Both cannot be literally true. `surfacingFor` therefore emits "No downstream billable stage ran." — true in both artifacts — and the UI copy should be aligned by its owner (F-05). Raised in the task comment (see §8).
