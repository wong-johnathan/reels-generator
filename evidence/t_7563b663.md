### 2. Two-connection proof — real pids, real loopback socket

`src/domain/generation-run.test.ts` (7 tests) drives a real `net.Server` on 127.0.0.1 as
the provider endpoint. The adapter records, per call, (a) whether a session that never
wrote the row sees it and (b) when the provider socket was accepted:

```
openAttempt returned committed run 64592345-… committedByBackendPid 5557
second session pid 5558 distinct from writer: true
row visible to second session: true {"status":"pending","charge_status":"pending",
                                     "idempotency_protected":false}
guard verified on backend pid 5559
committed job_attempt {"attempt_no":1,"status":"pending"}
```

The test asserts `observedAtMs <= socketAcceptedAtMs`, exactly one accepted socket, and
`verifiedOnBackendPid !== committedByBackendPid`. Negative cases: a forged run id, a row
deleted after commit, and an adapter registered for another stage each reach
`GenerationRunNotCommittedError` / `AdapterStageMismatchError` with **zero** provider
sockets opened. A `@ts-expect-error` case pins the type-level claim: a plain row literal
is not a `PersistedGenerationRun`.

## Deviations, decisions and limitations (read before integrating)

1. **`operator` row is not seeded here.** TECH_DESIGN §3.2 says "seeded at first
   migration"; LEAD_PLAN §4 assigns "argon2id seed" to **B-13** (auth). M-001 creates the
   table plus the exactly-one-row index; B-13 writes the row. Flagged as a comment on the
   card rather than chosen silently.
2. **pgvector is missing from the pinned Postgres image.** M-001 requires
   `CREATE EXTENSION vector` (TECH_DESIGN §3), but `compose.yaml` pins
   `postgres:16-alpine`, which does not ship pgvector. The migration fails closed with a
   message that names the fix; it is **not** changed in this diff because the runtime image
   pin (R-016) is a release decision. Recommended follow-up: pin
   `pgvector/pgvector:pg16@sha256:a97d77306ff47cc1d8add4d000cec2207da2e110746318df3137ce53c337ca30`
   (linux/amd64 digest resolved from Docker Hub) in `compose.yaml`. Until then a deploy on
   the current pin stops at M-001 with the actionable error.
3. **`idx_topic_project` is UNIQUE.** TECH_DESIGN lists `idx_topic_project(project_id)` as a
   plain index but states the invariant "one topic per project"; the unique index satisfies
   both, and keeps the design's index name.
4. **Extra CHECK constraints** encode invariants the design states in prose, so they cannot
   drift: `source.rerank_score >= 1.5` and non-empty URL for `accepted`; `object_key`
   derived from `content_sha256`; `claim.acknowledged_unsourced` needs who/when;
   `review_decision` reject needs reason + target stage; `narration_end_ms >= narration_start_ms`;
   `billed_units > 0` only when `charge_status = 'billed'`; a `timed_out` row is never
   `unbilled`; duration `10..180` on series/series_version/project.
5. **`INVALIDATION_RULE_SEED` duplication.** B-03 (branch `feat/t_90884a02`) exports the same
   §4.3 matrix as TypeScript data for M-005. M-005 seeds it from SQL (B-02 owns
   `src/db/migrations/**`; B-02 cannot depend on B-03). Integration should either make M-005
   the single source or have B-03 assert the table equals its seed. The runner test already
   pins the exact 8 rows, so drift fails a test.
6. **DB tests need `TEST_DATABASE_URL`** (a server with pgcrypto + pgvector, user with
   CREATEDB; each file provisions its own database and never issues a destructive
   statement). They skip loudly when it is absent. CI's `verify` job now starts a
   digest-pinned `pgvector/pgvector:pg16` service container, so Actions runs them.
7. **No Docker daemon on this host** and no Compose plugin: the `migrate` container,
   `compose up` and the real `postgres:16-alpine` image were not exercised. The same built
   artefact (`dist/src/db/migrate.js`) was executed directly against real PostgreSQL 16.14
   with pgcrypto 1.3 + pgvector 0.8.7 (a vendor embedded build, not the deployment image).
8. **Shared tree collision.** The shared workspace directory was on branch
   `feat/t_90884a02` (B-03) mid-run when this task started, so B-02 was developed and
   committed in a linked worktree `.worktrees/t_7563b663` on `feat/t_7563b663` off `3f70438`.
   Nothing in the shared tree's working copy or branch was modified.
9. Suite runtime is ~67 s with a database because PostgreSQL commits each DDL statement
   (M-001…M-005 ≈ 26 s on this NAS-backed disk); test timeouts are 120 s for that reason.
