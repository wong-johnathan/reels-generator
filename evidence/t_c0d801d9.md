### 2. Deterministic fake — PASS

`src/adapters/fake-text.ts` implements the same `TextAdapter` surface as the real adapter:
same-schema calls for one run return byte-identical results, `provider_request_id` is
`fake-<run prefix>-<schema version>` (distinct across runs, stable within one), it never imports
an HTTP client, and a scripted `responses` queue can inject a 5xx, a timeout or an
invalid-schema document deterministically.

Tests: `F1`…`F8` — `src/adapters/fake-text.test.ts` (8 tests, including "a stubbed global fetch
that throws is never called").

### 3. qualify() writes a provider_qualification pass row — PASS (DB-backed)

`qualify()` calls the adapter once per schema (topic, script, storyboard), each against a run
persisted through B-02's `openAttempt()`, then writes one `provider_qualification` row. Against a
real PostgreSQL 16.14 in a throwaway database:

    ✓ ... > opened one committed generation_run per schema before each qualification call
    ✓ ... > records a failing row when a schema check fails, and the gate then refuses
    ✓ ... > uses the newest row for the gate, so a later pass unblocks the adapter
    ✓ ... > refuses the gate when no qualification has ever been recorded
    ✓ ... > sends a deterministic qualification prompt per schema and serves the fixtures

The pass row is asserted durable on a **second connection** (a session that did not write it):

`passed=true`, `run_at` a timestamp, `details.adapter_version='text-adapter.v1'`, one check per
schema, schema hashes present. The committed-run half is asserted by counting
`generation_run` = 3 rows, stages `T/SC/SB`, all `pending/pending`, each with the schema version
qualification sent, and three distinct run ids in the recorded calls.

## Limitations (not silently chosen)

1. **The live DeepSeek endpoint was never called.** The rules forbid a paid provider in tests,
   so the wire contract is asserted with an injected `fetch` and the deterministic fake. The
   request body uses DeepSeek's documented JSON mode (`response_format: {type:'json_object'}`);
   the versioned zod schema is enforced locally and is the R-004-1 authority. A real production
   qualification pass row still requires the operator key and an ops caller (below).
2. **No env key for the text timeout.** `.env.example` / `src/config/env.ts` have
   `PROVIDER_TIMEOUT_IMAGE_S`, `_TTS_S`, `_SEARCH_S` but no `PROVIDER_TIMEOUT_TEXT_S`, so the
   60 s default (§5.1) is configurable only via the adapter constructor. Follow-up for the
   env/B-08 owner; not changed here to avoid editing B-01's env contract from this card.
3. **Rate limiting is in-process only.** TECH_DESIGN §5.7's Redis mirror (so a worker restart
   cannot reset the window) belongs to the worker layer (B-08) and is not in this diff.
4. **The gate call site is not wired.** `assertLatestQualificationPassed` is delivered and
   DB-tested, but the worker must call it before a billable call — B-08's `attempt.ts`.
5. **No retry/backoff in the adapter, by design.** It classifies (R-011-2); the 1 s/4 s/16 s,
   3-attempt loop and the `unknown charge` marking for `mayHaveBilled` are B-08.
6. **DB tests need `TEST_DATABASE_URL`** and skip loudly without it (the 29 skips above). Each
   migration set commits per DDL statement (~45 s), so the qualification file migrates once in
   `beforeAll` and removes only the rows it wrote between tests, inside a throwaway database.
7. **Qualification vs R-012-1 (open ruling).** `generation_run.project_id` is
   `NOT NULL`, so a production qualification call cannot open its attempt row before a project
   exists. This branch keeps the attempt-row rule (R-012-1) and requires the caller's `openRun`
   to persist a committed run, which an ops caller can satisfy with a qualification
   project/job. B-07 (`t_fa5e83c8`) raised the same tension as contradiction D-2 and solved it
   by exempting qualification runs. Both must be reconciled by a ruling before the ops
   qualification CLI (B-13); this branch does not silently choose.

8. **Production qualification has no CLI yet.** `qualify()` needs an `openRun` callback that
   persists a committed `generation_run`; the ops one-shot that supplies it (a job per stage) is
   B-13's `src/ops`.
