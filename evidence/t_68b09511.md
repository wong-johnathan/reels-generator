## Signal

> "scene grid shows per-scene state + provenance; first-three checkpoint blocks scenes 4+"

**Per-scene state**: `renderSceneGrid` emits one tile per scene of the 17-scene target
(`storyboardRows`/`sceneTiles` in `src/web/scenes/model.ts`). Each tile carries the state chip
(word, not colour alone — the shared chip's `DONE` / `NOT RUN` / `RUNNING` / `FAILED` /
`STALE` / `AWAITING APPROVAL` / `BLOCKED` / `CANCELLED`), the series pin tag
(`v3`), the scene id (`S04`), the narration span (`4.4 s`) and an `aria-label` of
`Scene 3 of 17, S03, done, 4.4 second narration, pin v3`. Provenance proper lives in S-13 and is
reached from the tile and from the S-11 row: the panel lists provider, model, prompt hash, seed,
series pin and creation time, and names the two fields the contract does not carry instead of
inventing them (`tests/web/scene-detail-page.test.ts > renders the provenance table …`).
Chromium: `evidence/f06/grid-ready-1280.png` (17/17 tiles with state + pin) and
`evidence/f06/detail-1280.png` (provenance panel).

**Checkpoint blocks scenes 4+**: `checkpointState()` returns `open` while `storyboard.first_three_reviewed` is
false and scenes remain (it returns `blocked` with the stage reason when there is no storyboard
yet, `not_applicable` when no scene uses the protagonist, and `cleared` once the first three are
reviewed); tiles 4–17 render `data-blocked="checkpoint"` and the
grid banner carries the exact copy `3 of 17 generated. Check the protagonist before releasing
the remaining 14 (14 image calls).` with the release CTA `Release remaining 14 · 14 image calls`.
S-13 for a scene ≥ 4 offers no replace control and prints `Scene 7 waits for the first-three
checkpoint release.` as the visible reason (AX-11), while scenes 1–3 stay replaceable.
Tests: `scenes-model.test.ts > first-three checkpoint …` (5), `scene-grid-page.test.ts >
renders 17 tiles and marks scenes 4+ as held by the checkpoint`, `scene-detail-page.test.ts >
is disabled with the checkpoint reason while scenes 4+ wait`, `app-scenes.test.ts > holds
scenes 4+ behind the checkpoint and names the reason in S-13`. Chromium:
`evidence/f06/grid-checkpoint-selected-1280.png`, `evidence/f06/grid-checkpoint-390.png`.

## Adjacent fix (declared, 3 lines)

`/assets/client/scene-grid.js` was not in either preview asset reader, so the S-12 enhancer would
have 404'd in the real app while its `<script type="module">` tag rendered. Both readers
(`src/web/authPreview.ts`, `src/web/preview.ts`) now map wire names to module files through a
`CLIENT_MODULE_FILES` table that includes `scene-grid` → `sceneGrid`; `preview.test.ts` asserts
200 + transpiled ESM + the `./behaviours.js` import. The F-05 handoff flagged the same class of gap
for `script-review.js`.

The workspace tab strip now has seven tabs; at 390 px it scrolled the _document_ 43 px
(`scrollWidth` 433). `.workspace-tablist` gains `overscroll-behavior-x: contain` and
`contain: layout` so the strip keeps its own horizontal scroll and the page never does (AX-14,
UI_SPEC §7.1 rule 1). Verified: `scrollWidth` 390 / `scrollX` 0 at 390 on the grid and detail
pages. This is also a genuine fix for S-11/S-12 rather than a drive-by.
