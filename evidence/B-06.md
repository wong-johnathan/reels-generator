## Signal line evidence

> "deterministic fake; reference-preserved-across-≥3-scenes qual recorded."

1. Deterministic fake — `fake-image.test.ts > is byte-for-byte deterministic for the same request
across instances` (identical bytes, provider request id and seed), `> is reproducible: two
qualification runs produce the same per-scene image hashes`.
2. Reference preserved across ≥3 scenes, recorded — real Postgres run (migrations M-001…M-005
   applied to a throwaway database on `127.0.0.1:55432`), row printed by the test:

```

"run_at":"2026-10-21T00:00:00.000Z","scene_count":3,
```

carries the same reference digest, distinct image hashes and a 768×1376 geometry.

## Limitations (not passes)

- **No live Gemini call was made.** No automated test calls a paid provider (task rule); the
  adapter's HTTP shape is asserted against an injected `fetch`, and the documented 768×1376
  geometry is validated by the parser, not by a real response. The production REST shape
  (`models/{model}:generateContent`, `contents[].parts[].inlineData`, `generationConfig.imageConfig`)
  has not been exercised against the provider in this task.
- **Real-provider qualification needs a human.** There is no automatic identity verifier for
  Gemini output. `runImageQualification({ adapter: GeminiImageAdapter })` records
  `passed=false, requires_human_review=true` with the three scene artefacts, and only an explicit
  operator verdict (`verdict: { passed, reviewer, notes }`) after visual review can record a pass.
  This is deliberate: inventing a visual pass would be worse than a closed gate. The three-image
  qualification run is billable and happens before any project pipeline exists; `billable_calls=3`
  is recorded in `details` so the cost is visible.
- **Queueing is not abortable.** The shared `TokenBucket` (B-05) accepts no `AbortSignal`, so a
  caller waiting for quota cannot be cancelled by the 60 s request timeout — the timeout starts
  after the token is granted. It waits rather than dropping (R-008-2) but a stuck queue is not
  cancellable from the adapter; noted for B-08's worker-level cancellation.
- **Rate limiter is in-process.** TECH_DESIGN §5.7 also asks for a Redis-mirrored bucket so a
  worker restart does not reset the window; that mirror belongs to the worker/queue task (B-08).
  The limiter is a seam (`RateLimiter`) so it can be swapped without touching the adapter.
- **DB-backed test needs a server** with pgcrypto + pgvector and `TEST_DATABASE_URL`; without it
  the test skips loudly (B-02 convention). CI starts a digest-pinned pgvector service (B-02).
- Retry/backoff execution (1 s/4 s/16 s, 3 attempts) is B-08. This task only classifies each
  failure (`transient` / `non_retryable`, `billedUnknown`, `retryAfterMs`) so B-08 can act on it.
