**Signal line (verbatim).** "login sets the session and every protected route redirects to /login"

**Result: PASS.** `POST /login` with valid credentials returns `303` with
`Set-Cookie: session=<43-char base64url>; Path=/; HttpOnly; SameSite=Lax`; the
cookie opens `/`. Without a session, `/`, `/series`, `/videos/:id/script`,
`/settings` and unknown paths all return `303` to `/login` with `required=1`
(or `expired=1` when the presented cookie no longer resolves) and the requested
destination preserved. No database, network or provider call is made.

## 5. Limitations and follow-ups (not in this diff)

- **L1 production mount.** `src/api/server.ts` is devbackend-owned (F-01 L1). INT-01 must mount `createWebApp({ sessions, authenticate, overview, health, csrfToken, assets })` from `src/web/app.ts` ahead of its 404 fallback and pass B-13's `SessionStore`/`Authenticate` plus a `readClientModule` that serves `dist/src/web/client/*.js`. The handler is production-shaped and is exercised over real HTTP in the preview; it contains no fixtures or fake credentials.
- **L2 CSRF.** TECH_DESIGN §11 requires a synchroniser token on state-changing routes and LEAD_PLAN assigns CSRF to B-13. The login form has no token field yet; B-13/INT-01 must add issuance + verification before release. This is a release-gate item, not a UI gap.
- **L3 login backoff.** S-01 renders the throttled state and `Retry-After`; the exponential backoff itself is B-13's.
- **L4 SY-2 draft preservation.** F-02 preserves the destination and shows the banner; the draft itself is persisted/restored by the editing screens (AX-21, F-05+). The banner must remain once those land.
- **L5 SY-3 copy and layout are design judgement.** UX_SPEC §2.1 names SY-3 but authors no copy or mockup; UI_SPEC has no SY-3 row. Copy is recorded in `NOT_FOUND_COPY` and raised for the lead's confirmation.
- **L6 session-expiry copy conflict inside UI_SPEC.** §6.1 says `…unsaved draft…`, §8.5 says `…draft…`, §9.5 says `…saved draft…`. F-02 uses §6.1 for the visible banner and §8.5 for the assertive announcement; task comment raised.
- **L7 no-access (403).** The renderer and tests exist; no F-02 route currently returns 403 (single operator, no roles). Later cards can call the same renderer.
- **L8 reveal control.** UI_SPEC asks for a 32 px eye button; the spec ships no icon set (§2.6), so the control is a 32 px text button reading `Show`/`Hide` with an accessible name — the same trade-off F-01 recorded for rail glyphs.
- **L9 chrome-free SY-3.** The system page has no rail or status strip; UX_SPEC does not specify SY-3 layout, and a 404 should not imply a current navigation destination.
- **L10 session lifetime.** 12 h absolute is design judgement (TECH_DESIGN defines `expires_at`, not a duration). The cookie has no `Max-Age`, so closing the browser also ends the session (no "remember me" in UI_SPEC §6.1).
- **L11 preview credential.** `operator / preview` exists only in `src/web/authPreview.ts` (dev surface, in-memory). It is not read by the production entrypoint and is not in the image path.
